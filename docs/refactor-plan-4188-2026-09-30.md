# Biu 按 4188 设计稿重构计划

> 日期：2026-09-30  
> 唯一视觉与交互基准：`http://127.0.0.1:4188/`  
> 范围原则：保留当前项目全部业务能力与数据语义；设计稿只决定呈现与交互，不扩张业务边界。当前阶段主题明确收敛为单一深色主题。  
> 本文基于本轮实际浏览设计稿、检查源码、现有截图与测试入口形成。仓库原 `docs/design/*` 属于上一版 C+ 方案，只作为当前实现历史，不作为本轮视觉真值。

## 1. 审计结论摘要

当前代码已完成一轮以“无侧栏 C+ 壳层”为目标的重构，而 4188 设计稿采用“常驻左侧导航 + 顶部搜索 + 底部播放器”的桌面音乐应用壳层。两者不是同一版设计。业务模型、store、service、Electron IPC、播放/下载能力大部分可以保留；需要重做的主要是 `src/app/shell`、`src/layout`、页面装配与 UI 组件层。

实施必须先冻结 4188 真值，停止继续以 `docs/design/cplus-spec-lock.json` 为验收基准。旧真值、旧 fixture、旧 fidelity 脚本不能直接删除，应先建立 4188 对应的新版映射和截图基线，待全部页面切换且回归通过后再清理。

## 2. 设计稿实际清单

### 2.1 全局结构与导航

本轮在设计稿中实际检查到：

- 左侧主导航：发现音乐、我的音乐、稍后播放、本地音乐、下载管理。
- “内容与应用”区：新建播放列表、播放队列、观看历史、关注与动态、设置。
- 账户区：头像、昵称、登录状态、账户入口。
- 顶栏：返回、前进、全局搜索、Enter 快捷提示。
- 底部播放器：封面、曲名、作者、音质、收藏、更多、随机/上一首/播放暂停/下一首/循环、进度、歌词、快进、队列、音量。
- 页面区独立滚动；侧栏、顶栏和播放器保持稳定。
- 播放队列既可作为右侧浮层出现，也有完整页面入口；沉浸播放页隐藏标准壳层。

### 2.3 实测设计规范

以下数据来自浏览器实际计算样式与响应式检查，不是目测推断：

- 基础字体：`Inter, Noto Sans SC, PingFang SC, system-ui, sans-serif`。
- 页面底色：`rgb(9, 11, 18)`；主文字：`rgb(245, 247, 251)`；弱文字在设计稿变量中为 `#9da8ba`。
- 页面 H1：38px、700；上方 eyebrow：12px、650、紫色 `rgb(157,148,255)`。
- 顶栏搜索输入：14px；顶栏高 80px。
- 标准宽度下侧栏 220px；背景为 `rgb(18,24,36) → rgb(17,22,32)` 纵向渐变。
- 底部播放器高 100px。
- 1024×768：侧栏仍为 220px，内容宽 804px；无页面级横向滚动。
- 720×900：侧栏收为 78px，仅保留图标与头像；内容宽 642px；播放器仍为 100px；页面内容独立滚动。
- 设计语言：深蓝黑底、紫色主操作、青色播放进度/当前状态、低对比描边、12–20px 卡片圆角、药丸筛选、当前行蓝黑高亮。
- 图标均为一致的线性图标体系；不使用 emoji、文本符号或页面自制 SVG 近似替代。
- 动效需从设计稿实际交互提取：导航/药丸/卡片 hover，按钮 press，焦点光环，抽屉开合，页面切换，播放态切换，进度动画。统一使用令牌，不允许各页自行定义时长与 easing。

### 2.4 组件状态规范（目标）

每个公共控件必须至少覆盖：

| 状态 | 目标表现                     | 验证重点                                             |
| ---- | ---------------------------- | ---------------------------------------------------- |
| 默认 | 中低对比表面，文字层级清楚   | 颜色、边框、图标基线                                 |
| 悬停 | 表面提亮或紫色弱反馈         | 不导致尺寸位移                                       |
| 聚焦 | 可见且连续的紫色焦点环       | 键盘可达，不能只依赖 hover                           |
| 按下 | 表面压暗/缩放或高光变化      | 反馈短、无布局抖动                                   |
| 选中 | 紫色填充/左侧指示/当前行高亮 | `aria-current`、`aria-selected`、`aria-checked` 同步 |
| 禁用 | 降低对比且不可触发           | 保持可辨，不只用透明度隐藏                           |
| 加载 | 原尺寸内 spinner/skeleton    | 不造成跳动，提供状态文本                             |
| 空   | 说明原因 + 下一步操作        | 不伪造数据                                           |
| 错误 | 红色语义 + 重试/恢复路径     | 错误可读、可恢复                                     |

## 5. 差异与冲突列表

### 已确认的 P0 决策

1. **壳层**：以 4188 为准重建侧栏，同时保留顶部搜索和底部播放器。
2. **搜索业务口径**：“歌曲”映射现有 B 站音乐视频；“播放列表”只聚合当前用户已有歌单、收藏夹、合集与系列，不新增远程能力。
3. **主题**：当前阶段只保留 4188 深色主题。浅色、跟随系统、自定义主色和背景不进入本轮目标 UI；旧持久化字段仍需兼容读取，并归一到深色，避免旧配置导致异常或不可读状态。
4. **队列双形态**：保留队列抽屉与 `/queue` 完整页面，两者共享同一个 `QueueViewModel` 和 store；抽屉用于快速管理，页面用于完整操作。
5. **设置分类**：“关于”作为独立第六类保留，不并入“高级”。
6. **视觉真值**：4188 地址可能变化，不以 URL 的持续可用性作为长期真值；以其源文件及从源文件生成的版本化截图、测量数据为准。

### P1 差异

- 当前顶部段导航需迁回侧栏/页内药丸；`route-shell.ts` 的段组契约需要重写而非继续扩展。
- 当前 UI 混用 HeroUI、Tailwind 任意值与新版 `src/ui` 组件；需统一状态、尺寸和令牌消费。
- 旧 C+ 字号（56px 页面标题）与 4188 实测 H1 38px 差异显著。
- 当前播放器高度 88px，4188 为 100px；顶栏当前旧基线 71px，4188 为 80px。
- 当前设置页、搜索页仍存在旧 HeroUI 页面实现与 fixture 呈现层并存，容易造成正式路径和截图路径不一致。
- 设计稿没有完整展示登录二维码、收藏夹编辑/删除、图片裁剪、代理、导入导出、更新、异常/空态；必须用 4188 的弹窗、卡片、表单和反馈语言补齐。

## 6. 目标设计系统与公共组件

### 6.1 设计令牌

建立 `src/ui/tokens/4188/{palette,semantic,geometry,motion}.css` 或等价的单一令牌入口，至少包含：

- 颜色：只建立深色主题的 canvas、sidebar、topbar、player、surface 1–4、hover、pressed、selected、border、text 1–4、accent purple、playing cyan、success/warning/danger、focus、scrim。
- 排版：eyebrow 12/650、chrome 14、body 14/16、section title、page title 38/700、track title、numeric（tabular nums）。
- 几何：sidebar 220/78、topbar 80、player 100、内容 gutter、表格行高、封面尺寸、卡片圆角、药丸、弹窗、抽屉宽度。
- 动效：fast/normal/slow、standard/emphasized easing、reduced-motion 降级。
- 层级：content、sticky chrome、drawer、popover、modal、toast。

禁止页面写新的相似色、圆角、阴影和 transition；`tools/design-fidelity/check-literals.mjs` 要升级为检查 4188 令牌。

## 7. 分阶段执行计划

### 阶段 0：冻结真值与现状（P0，2–3 天）

**状态：已完成（2026-09-30）**。阶段产物见 [`docs/design-4188/`](./design-4188/README.md)，包含源文件哈希锁、四档视口测量、17 个页面/状态矩阵、功能映射、证据索引、偏差台账与统一验证协议。源文件完整性可通过 `node tools/design-4188/verify-source-lock.mjs` 检查。

- **目标**：建立本轮唯一可追溯基线，阻止继续混用旧 C+ 方案。
- **设计依据**：4188 全部页面、抽屉、沉浸页、720/1024/标准桌面视口。
- **涉及文件**：新增 4188 截图/测量/矩阵；标记 `docs/design/*` 为历史；更新 fidelity 配置但暂不改产品代码。
- **保留行为**：所有现有路由、store、service、IPC、持久化数据。
- **改造**：为每个页面定义固定 fixture URL、视口、数据和状态；建立“设计—现状—目标”矩阵和偏差登记表。
- **依赖**：无；是所有后续阶段前置。
- **完成标准**：设计主状态均有截图；每个现有路由有功能所有者；冲突有决定或明确阻塞；截图可重复生成。
- **风险/回退**：设计稿动态变化导致基线漂移；回退为锁定本轮截图与测量版本，不自动跟随 URL 后续变化。

### 阶段 1：令牌与状态契约（P0，3–5 天）

**状态：已完成（2026-09-30）**。已建立 `.biu-theme-4188` 作用域的四层令牌、状态契约、旧主题读取兼容策略、字面色护栏和独立校验脚本；未替换旧页面的 C+ 令牌，避免迁移前视觉污染。

- **目标**：把 4188 实测视觉规则固化为唯一令牌。
- **设计依据**：全局壳层、导航选中态、搜索聚焦态、按钮/药丸、卡片、表格当前行、进度条、抽屉。
- **涉及文件**：`src/ui/tokens/*`、`src/app.css`、`src/pages/design-system/*`、令牌测试与 literal 检查。

## 8. 视觉与功能回归清单

### 8.1 每个页面/组件必做

1. 固定 fixture 数据、视口、滚动位置和 UI 状态。
2. 同尺寸截图并排与像素差对比；检查位置、尺寸、间距、字体、颜色、圆角、阴影、图标。
3. 检查默认、hover、focus、pressed、selected、disabled、loading、empty、error、permission。
4. 检查鼠标、键盘、快捷键和屏幕阅读器名称。
5. 检查 1440/1024/720 与 200% 缩放；确保无横向滚动、遮挡和不可达操作。
6. 运行该页涉及的 P0/P1 功能场景以及全部播放 P0。
7. 在偏差台账记录任何必须偏离设计稿的原因、影响、替代方案和批准人；未批准不得合并。

### 8.2 自动门禁

- `pnpm test --run`：领域、store、adapter、page model、组件交互。
- `pnpm build`：Web/Electron 生产编译。
- 新 `verify:4188`：逐页截图、结构锚点、像素差和响应式视口。
- `verify:literals`：禁止业务页新增色值/阴影/圆角/动效字面量。
- 路由与功能矩阵测试：所有现有入口仍可达；旧兼容路由仍能跳转。
- 可访问性：axe 或等价静态检查 + 键盘人工巡检；不得据此声称完整 WCAG 合规。

### 8.3 人工桌面回归

- 在线/本地播放、播放模式、分 P、队列拖排、进度恢复、歌词。
- 登录/退出/失效、收藏夹 CRUD/排序、关注/取消关注。
- 扫描/重新扫描/移除目录，不误删本地文件。
- 下载全状态、暂停/继续/失败重试/定位/FFmpeg 缺失。
- 系统媒体键、全局快捷键、托盘、关闭行为、开机启动、Mini 同步。
- 设置持久化、旧配置导入与深色归一、代理、更新检查、字体。

## 9. 防漂移机制

- 4188 截图、测量 JSON、页面矩阵、令牌版本同一次提交冻结。
- 页面只能使用公共令牌和公共组件；例外必须在偏差台账登记。
- 已验收组件通过视觉快照和 contract test 锁定；后续改动必须展示受影响页面清单。
- 每阶段只允许修改声明范围内的页面；跨阶段公共件变化要重跑所有已验收页面。
- 正式路径与 fixture 路径必须共用同一呈现组件，不允许“截图专用页面”。
- 验收对象始终是 4188 冻结截图，不是仓库旧 C+ reference，也不是实现者主观判断。

## 10. 依赖、风险与已确认决策

### 外部/环境依赖

- 本地测试当前被 Node 版本阻塞：项目要求 22.17.1，检查环境为 20.20.2；开始实施前需统一 Node 版本。
- 视觉回归需要可重复启动的 Web fixture；Electron 专属能力仍需 macOS 真实窗口验收。
- 登录、关注、收藏、历史和在线下载需要可用测试账号与网络；不得把真实用户数据写进 fixture。

### 主要风险

- 旧 C+ 方案与 4188 新设计混用造成第二次风格漂移。
- 搜索 UI 暗示不存在的远程能力。
- 旧浅色/自定义主题配置若未正确归一，可能导致升级后局部不可读或启动异常。
- 队列抽屉和页面出现双状态源。
- 大规模壳层切换同时影响全部路由和 Electron 窗口。
- 仅做截图而遗漏真实账号、IPC、持久化和系统集成回归。

### 已确认的产品/设计决策

1. “歌曲”等同于现有 B 站音乐视频；“播放列表”仅聚合当前用户已有歌单与收藏资产。
2. 当前阶段只保留深色主题；旧主题配置需要兼容读取并归一到深色。
3. 播放队列抽屉与 `/queue` 页面都保留，并共享模型与状态源。
4. “关于”作为设置的第六分类保留。
5. 4188 URL 可能变化；整体以设计源文件为准。阶段 0 必须从源文件导出并版本化冻结截图、测量数据和资源清单，URL 只作为本轮检查入口。

## 11. 最终完成定义

- 当前项目的所有现有业务能力都有明确入口并通过回归，没有因设计稿未展示而删除、隐藏或弱化。
- 4188 覆盖的页面在标准桌面、1024 与 720 视口下通过视觉和交互验收。
- 未覆盖功能全部复用同一令牌、组件、布局层级和反馈模式。
- 没有未批准的视觉/交互偏差，没有截图专用实现，没有长期双轨 UI。
- 全部 P0/P1 测试、生产构建和真实 Electron 冒烟通过；偏差、限制与未覆盖项都有可追溯记录。
