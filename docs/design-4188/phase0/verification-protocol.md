# 4188 统一验证协议

## 1. 源文件完整性

实施或验收前计算 `source-lock.json` 所列文件的 SHA-256。任何变化都必须暂停视觉实现，先更新屏幕矩阵、测量和偏差登记。

## 2. 固定视口

每个标准页面至少检查：

- 1440×1024：完整桌面。
- 1024×768：中等桌面与队列覆盖。
- 720×900：78px 紧凑侧栏。
- 390×844：移动壳层。

页面涉及沉浸态或 Mini 窗口时，增加其真实目标尺寸。

## 3. 固定状态

每个页面根据 `screen-matrix.md` 固定 fixture、滚动位置、搜索词、当前曲目和弹窗。正式路径和 fixture 必须共用同一呈现组件。

## 4. 截图比对

同一视口、同一数据、同一状态下检查：

- 壳层尺寸、内容起点、滚动区和覆盖关系。
- 字体族、字号、字重、行高和数字等宽。
- 颜色、透明度、渐变、边框、圆角、阴影和模糊。
- 图标库、图标尺寸、封面裁切和焦点环。
- default/hover/focus/pressed/selected/disabled/loading/empty/error。

像素差只能作为报警信号；所有差异必须回到源文件和 DOM 几何解释。

## 5. 功能回归

页面验收同时运行对应 P0/P1 场景。任何视觉完成但播放、收藏、下载、登录、持久化或 Electron 集成退化的页面都不能标记完成。

## 6. 阶段边界

- 已验收公共组件变更时，重跑全部消费者页面。
- 页面不得定义公共组件已有的相似色、圆角、阴影或动效。
- 后续阶段不得覆盖已锁定令牌；如必须改变，先登记偏差和影响范围。
- 不使用仓库旧 `docs/design/cplus-spec-lock.json` 作为 4188 验收线。

## 7. 可访问性限制

截图只能发现可见风险，不能证明完整合规。必须另做键盘顺序、语义名称、状态公告、缩放/reflow、reduced-motion 和真实辅助技术检查。
